## 一、先定人设：你不是"做界面的"，你是"把算法过程讲清楚的人"

**自我介绍模板（30 秒）：**

> 我负责前端部分，大概 4700 行代码：界面、图结构可视化、遍历和最大流的逐步动画、
> 过程解说、还有供应链场景的业务层。算法核心是队友用 C++ 写的，通过 8 个返回 JSON 的
> 接口给到我；前端不重写算法，但有一份 JS 兜底实现，保证没装 Emscripten 的机器上也能演示，
> 两边结果用 160 项一致性自检锁死。

**三个必须打出去的亮点**（任何问题都可以往这三点上引）：

1. **图层机制**：算法和渲染解耦。核心只返回数据，我把它翻译成"高亮图层"，
   遍历图层和最大流图层可以叠加，画布按图层加 CSS class 渲染，不是手动改 DOM。
2. **逐帧解说 + 交叉自校验**：最大流每一步我用 `steps` 重放残余网络生成解说帧，
   并且自己校验 S 侧和割边容量和，和核心对不上就降级讲解（`verified=false`）——
   前端不盲信后端。
3. **屏幕像素化渲染**：Cytoscape 的长度单位是模型坐标、会跟着缩放变，
   我把所有尺寸乘 `1/zoom` 换算成屏幕像素，所以换布局、随便缩放，点的直径始终是 28px。

**备选亮点**：性能分级降级（260 / 400 / 150 三个阈值）；双后端可插拔（WASM / JS 同一套接口）。

## 三、问答全集（按类别，答法可直接说）

### A. 项目与架构

| 问题 | 怎么答 |
| --- | --- |
| 你这个网页比命令行版多了什么？ | 命令行只给最终答案，网页能看**过程**：遍历一步步走、增广路一条条推、残余网络余额怎么减、割边是哪几条、序列为什么合法。前端是算法过程的讲解器。 |
| 整体架构怎么分的？ | 三层：C++ 算法核心 → 适配层（binding.cpp 输出 JSON，loader.js 解析）→ 前端（store 存状态、组件渲染、Cytoscape 画图）。 |
| 前端负责哪些代码？ | `src/` 全部约 4700 行 + 前端自检 `tools/selftest.mjs` 360 行；后端负责 `cpp/` + `binding.cpp` + 构建脚本。 |
| 数据从后端到画布怎么走的？ | 组件调 `loader.js` 拿 JSON → 写进 `graphStore` → 各组件 `computed` 派生 → `GraphCanvas` 合并图层成 CSS class → Cytoscape 重绘。 |
| 为什么不用 Pinia / Vuex？ | 只有一张图、两个图层、一份解说状态，一个 `reactive` 单例就够，少一个依赖少一层概念。 |
| 为什么选 Vue 3 而不是 React / 原生 JS？ | 单文件组件把模板/逻辑/样式放一起，组合式 API 逻辑可复用；响应式让"数据变了界面就变"，画布只需关心"数据 → class"的映射。 |

### B. Vue / 响应式 / 组件

| 问题 | 怎么答 |
| --- | --- |
| `core` 为什么放在响应式系统外面？ | WASM 模块是巨大对象，放进 `reactive` 会被深度代理、白白浪费性能；算法结果通过 `store.graph` 传出来就够了。所以用模块级 `let core` + `coreRef()`。 |
| 组件之间怎么通信？ | 全部通过 `graphStore` 共享状态，没有 props / emit。唯一例外：`FlowNarrator` 通过 `store.flowControls` 反向调用 `FlowAnimation` 的播放控制。 |
| `computed` 和 `watch` 分别用在哪？ | `computed` 派生展示数据（矩阵文字、合并图层）；`watch` 做副作用（帧变了写图层、速度变了重启定时器、卸载清理）。 |
| 为什么分块切换用 `v-show` 不用 `v-if`？ | `v-if` 会真正销毁组件：`FlowAnimation` 卸载时会清空 `store.flowControls` 和最大流图层，供应链面板"载入示例自动算最大流"就找不到计算入口；动画进度也会丢。`v-show` 只隐藏，状态保留。 |
| toast 为什么要 `seq` 计数？ | 同一句文案连续提示两次，对象里除 `seq` 外没变化，`watch` 不会触发；`seq` 每次 +1 保证能重新弹。 |
| 组件销毁时做了什么清理？ | 画布断开 `ResizeObserver` 并 `cy.destroy()`；两个动画面板清 `setInterval` 并清空图层；`FlowAnimation` 把 `flowControls` 置 null；导出图片用了 `URL.revokeObjectURL`。 |
| 有没有内存泄漏风险？ | 定时器、观察器、Cytoscape 实例都在 `onBeforeUnmount` 清理；项目里没有全局事件监听。 |

### C. 画布 / Cytoscape

| 问题 | 怎么答 |
| --- | --- |
| 图怎么画出来的？ | `graph.nodes/edges` 转成 Cytoscape 元素（节点 `n1`、边 `e1_2`），外观统一由样式表控制，高亮靠加 class。 |
| 点的直径为什么乘 `1/zoom`？ | Cytoscape 的长度单位是模型坐标，会随缩放一起变；乘 `1/zoom` 换算成屏幕像素，这样换布局（各布局 fit 后缩放不同）或手动缩放，点看起来都一样大。 |
| `fit` 之后为什么还要再 restyle？ | `fit` 改变缩放，缩放变了所有尺寸要按新的 `1/zoom` 重算，所以是 `restyle → fit → restyle`。 |
| 反向弧怎么画？ | 给每条边额外建一条方向相反的弧（id 带 `r` 前缀），默认 `display:none`；只有正方向推过流、残余网络真有余额时才显示，青蓝虚线 + 贝塞尔曲线错开，避免和正向边重叠。 |
| 为什么力导向在点多时会慢？ | `cose` 是 O(n²) 迭代力导向，>260 点自动降级成环形并提示。 |
| 布局切换为什么监听 `layoutstop`？ | 布局有动画，必须等它停下来再按最终缩放校正尺寸，否则点大小算错。 |
| 容器尺寸变了怎么办？ | 用 `ResizeObserver` 监听画布容器（左侧栏展开/收起也会变），触发 `cy.resize()`；监听 `window.resize` 抓不到这种情况。 |
| 导出图片怎么保证清晰？ | `cy.png({full:true, scale:2})`：2 倍分辨率 + 指定深色背景。 |

### D. 动画与状态同步

| 问题 | 怎么答 |
| --- | --- |
| 遍历动画怎么做的？ | 核心返回 `seq` + `parentEdges`，前端按"毫秒/步"推进 `index`，`watch([result, index])` 触发 `applyLayer()`：已访问 `visited`、当前点 `current`、树边 `tree`。 |
| 为什么用 `setInterval` 不用 `requestAnimationFrame`？ | 速度是离散的"毫秒/步"，还要支持暂停/单步/跳转；`rAF` 是每帧回调，反而要自己累计时间。 |
| 拖动速度滑块为什么动画会重启？ | `watch(speed)` 里主动重启定时器，让新速度立刻生效。 |
| 播放中换图会怎样？ | `watch(store.graph)` 停表、清空结果和图层，避免旧序列和新图对不上。 |
| 画布上的"余额"数字哪来的？ | narrator 用 `steps` 重放残余网络算出来的（和 C++ 内部残余网络一致，因为更新顺序一致），每一帧重新算边标签。 |
| 右侧解说栏怎么和画布同步？ | `FlowAnimation` 是唯一写方，写 `store.flowFrame/index/total`；`FlowNarrator` 只读，点时间线时通过 `flowControls.jump(i)` 反向控制。 |

### E. 性能与边界

| 问题 | 怎么答 |
| --- | --- |
| 图很大时会卡吗？ | 分级降级：>260 点力导向换环形、>400 条边不建反向弧、>150 点不铺邻接矩阵表（算法照算），页面上都有提示。 |
| 为什么限制 2000 点？ | 容量矩阵是 O(n²)，2000 点约 16MB；再大就该换成边数组 + 反向边下标（Dinic 那种写法）。 |
| 支持 0 开始编号的图文件吗？ | 支持，后端读完文件统一 +1 映射成 1..n，并返回 `base` 字段，前端会 toast 提示"已自动映射成 1..n"。 |
| JSON 解析失败会怎样？ | `loader.js` 里 catch 住返回 `{ok:false,error}`，页面弹提示而不是白屏。 |

## 四、后端算法你要能讲清楚（前端版讲法）

### 1. 图的存储（邻接表 + 容量矩阵）

> "遍历要枚举某个点的所有邻居，用邻接表 O(度数)；最大流要频繁问'这条弧还剩多少余额'，
> 用容量矩阵 O(1)。代价是矩阵占 O(n²)，n 上限 2000 约 16MB，课程设计规模可以接受。"

### 2. DFS / BFS

> "DFS 用递归（等价于栈），BFS 用队列。两者都顺带记录每个点是跟着谁走过来的（父节点），
> 变成'树边'返回给前端，所以动画能把走过的边高亮出来。"

### 3. 遍历序列合法性判别（最有含量，务必讲）

> "合法序列不唯一，所以程序不是拿输入去比对标准答案，而是**按遍历规则检查这个序列真能不能走出来**。
> DFS：用栈模拟，栈顶只要还有未访问的邻居就必须继续深入，所以下一个点必须是
> '把已经没有未访问邻居的栈顶全部弹掉之后'的新栈顶的邻接点；最后长度还要等于该起点的连通块大小。
> BFS：算每个点的层数（前面最早出现的邻居层数 +1），层数沿序列不能减，同层点的父节点
> 出现位置也不能减——因为队列先进先出，先处理的父亲，孩子一定先出队。"

### 4. 最大流最小割（Ford-Fulkerson）

> "残余网络初始等于容量矩阵；反复找一条 s 到 t 余额都大于 0 的增广路，
> 瓶颈是路上最小的余额，然后正向弧余额减瓶颈、反向弧余额加瓶颈；找不到就结束，
> 累加值就是最大流。反方向加回来的那条弧就是'反向弧'，意义是**把之前推过去的流量撤回来**。"

**必须会讲的例子（实测）**：`rev.txt`（4 个点）最大流是 2，两条增广路是
`1-2-3-4` 和 **`1-3-2-4`**。第二条里的 3→2 在原图里根本不存在，是残余网络里的反向弧；
不会撤流的话这张图只能得到 1。

**最小割的求法**：

> "在最终残余网络里从 s 出发能走到的点组成 S，剩下的是 T，原图里 S→T 的边就是割边，
> 容量和等于最大流。程序自己也校验这一点（返回 `correct`），界面会显示'最大流 = 最小割 ✓'。"

**深水区追问**：

| 追问 | 回答 |
| --- | --- |
| 复杂度？ | 遍历 O(n+m)；Ford-Fulkerson O(E·f)，f 是最大流值，**是伪多项式**；改进方向 Edmonds-Karp O(V·E²)、Dinic O(V²E)。 |
| 为什么一定停？ | 整数容量下每次瓶颈至少 1，总流量有上界；另有 200000 次上限保护。 |
| 无向图怎么算？ | 容量矩阵对称，两个方向各一条独立弧；净流量可能为负，显示按 0。 |

### 5. 随机建图

> "稀疏时随机抽两点当边、重复就重抽；稠密时抽签几乎必然重复会极慢，改成枚举所有可能的边
> 打乱后取前 m 条。`seed` 非 0 时用 `mt19937` 可完全复现同一张图。"

### 6. 文件解析与 0 编号兼容

> "先整体读入、全部校验通过才建表（防越界），兼容 BOM、空行、`#`/`%`/`//` 注释、
> 逗号分号分隔、容量省略；0 开始编号的文件在 IO 层统一 +1 映射成 1..n，
> 返回 `base` 字段让前端提示一句，算法层不用管编号基准。"
