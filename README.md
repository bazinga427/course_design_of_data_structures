# 图的遍历课程设计

用 C++ 实现图的建立、存储、遍历、遍历序列判别、最大流最小割，控制台菜单操作，
之后会加 EasyX 可视化界面。

## 现在能做什么

| 功能 | 说明 |
| --- | --- |
| 建图 | 从文件读入，或随机生成（可指定种子复现同一张图） |
| 存储 | 邻接表（遍历用）+ 容量矩阵（最大流以后直接用） |
| 遍历 | DFS、BFS，起点可以自己指定 |
| 判别 | 判断一个序列是不是合法的 DFS / BFS 遍历序列 |
| 最大流 / 最小割 | Ford-Fulkerson 算法，顺便求出最小割，并自动校验两者相等 |
| 输出 | 打印邻接表、容量矩阵；把当前图存回文件 |

## 环境要求

- Windows，64 位。EasyX 是基于 Win32 GDI 的库，只能在 Windows 上用。
- 64 位 MinGW-w64 的 `g++`（本项目在 g++ 11.4.0 / x86_64-w64-mingw32 上验证通过）。
- EasyX 已经放在 `third_party/easyx` 里，**不需要另外安装**。

## 编译与运行

三种方式任选：

1. 双击 `build.bat`。
2. 用 VSCode 打开本文件夹，按 `Ctrl+Shift+B`。
3. 命令行手动敲：

```
g++ -std=c++17 -O2 -static -static-libgcc -static-libstdc++ -I third_party/easyx/include -L third_party/easyx/lib64 main.cpp graph.cpp flow.cpp -o main.exe -leasyx
```

编译出来的 `main.exe` 是静态链接的，只用 Windows 自带的系统 DLL（KERNEL32 / USER32 / SHELL32 / msvcrt），
拷到任何一台 64 位 Windows 上都能直接跑，对方不需要装 MinGW，也不需要装 EasyX。

程序用相对路径读数据文件，所以 `main.exe` 要和 `graph.txt`、`graph2.txt` 放在同一个文件夹里。

## 数据文件格式

第一行是 `n m is_directed`（节点数、边数、1 = 有向图 / 0 = 无向图），
后面每行一条边 `u v [容量]`，容量可以不写，不写就是 1。**节点编号从 1 开始。**

```
6 8 1
1 2 3
1 3 2
...
```

仓库里带了两张示例图：`graph.txt`（6 个点的有向图，带容量）、`graph2.txt`（5 个点的无向图）。

## 最大流最小割（Ford-Fulkerson）

菜单第 9 项，输入起点（源）和终点（汇）即可。算法本身只有四步：

1. 残留网络一开始就等于容量矩阵。
2. 在残留网络里找一条从源点到汇点的增广路（路上每条边的剩余容量都大于 0）。
3. 这条路上能推的流量 = 路上最小的剩余容量（瓶颈）。
4. 沿路更新残留网络：正向边剩余容量减掉瓶颈，**反向边加上瓶颈**，然后回到第 2 步。
   找不到增广路时，累计的流量就是最大流。

第 4 步里的"反向边"就是视频里最容易看不懂的地方：它的作用是**撤销**之前的错误决定。
如果某一趟选的路把边占满了、后来发现更好的走法要用到这条边，反向边就让流量"退回去"重新分配。

最小割是顺便求出来的：在最后的残留网络里，从源点出发能走到的点组成 S，走不到的点组成 T，
从 S 指向 T 的边就是割边。程序会打印割边和 `割边容量之和`，并且自动检查它是否等于最大流
（最大流最小割定理），相等就说明这次计算是对的，答辩时可以直接拿这一行当验证。

程序还会把每一趟增广路和每条边的流量（`流量/容量`）都打印出来。所有增广过程都记录在
`FlowResult::steps` 里，以后做 EasyX 动画时按这个一步步播就行，不用改动算法。

## 可复现性

如果要在别的电脑上（或者答辩时）复现同一份结果：

- 随机生成会把用到的种子打印出来，下次填同一个种子就能得到完全一样的图。
- 菜单第 8 项可以把当前图存成文件，以后直接按文件读入。
- 依赖库 EasyX 已经提交进仓库，队友 clone 下来不需要额外装环境就能编译。
- `main.exe` 是编译产物，已经被 `.gitignore` 忽略，不要提交；交作业时再和项目一起拷。
