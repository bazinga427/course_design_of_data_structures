## 编译与运行

环境要求：Windows 系统 + MinGW-w64 的 g++（EasyX 图形库已经放进本仓库的 `third_party` 目录，不需要另外安装）。

两种编译方式，任选一种：

1. 用 VSCode 打开本文件夹，按 `Ctrl+Shift+B`。
2. 直接双击 `build.bat`。

这两个都用**绝对路径**调用 `D:\soft\mingw64\bin\g++.exe`（`build.bat` 里找不到时会退回 PATH 里的 `g++`）。
之所以不直接写 `g++`：电脑上如果还装着 Dev-Cpp、MSYS2 或者别的旧 MinGW，PATH 里先被找到的可能是 32 位或旧版本的编译器，
链接 EasyX 时会报一堆看不出来的错。换电脑的话，把 `build.bat` 和 `.vscode\tasks.json` 里的这个路径改成新位置即可。

编译出来的 `main.exe` 是静态链接的，可以拷到任何一台 Windows 电脑上直接运行，对方不需要安装 MinGW 或 EasyX。注意：程序用相对路径读取 `graph.txt` / `graph2.txt`，所以 exe 要和这些数据文件放在同一个文件夹里。

需要注意的一个坑：本机 MinGW 自带的 `graphics.h` 其实是 EGE 图形库的，会和 EasyX 冲突。所以编译时必须加上 `-I third_party/easyx/include` 参数，`tasks.json` 和 `build.bat` 里已经写好了。

还有一个坑（只有 UCRT 版 MinGW 才会遇到）：`third_party/easyx/lib64/libeasyx.a` 是用 msvcrt 版编译器（TDM-GCC 那一类）编出来的。如果你的 g++ 是 UCRT 版（`g++ -v` 的输出里能看到 `ucrt` 字样），只加 `-leasyx` 会报 `undefined reference to __imp___iob_func`。仓库里的 `tools/easyx_ucrt_compat.c` 就是补这个符号用的，编译时把它一起带上即可（`tasks.json`、`build.bat`、`tools/run_demo.bat` 里都已经加好了）。注意不要改用 `-lmsvcrt-os` 去补：那会让 msvcrt.dll 和 UCRT 混在同一个进程里，带 `-static` 的程序会直接堆损坏崩溃。

## 显示图结构（EasyX 可视化）与文件的保存 / 加载

对应文件：

| 文件 | 作用 |
| --- | --- |
| `ui.cpp` / `ui.h` | 可视化窗口：绘制、拖拽、缩放、滚动条、选中节点、打开/保存/导出 |
| `layout.cpp` / `layout.h` | 节点的自动布局：圆环布局、力导向布局、随机布局 |
| `graph_io.cpp` / `graph_io.h` | 图结构文件的读取与保存、节点坐标文件、节点编号识别 |

运行 `main.exe` 后选 `1`（或直接 `main.exe 1`）就会打开图形窗口。窗口里可以：

* **显示**：节点画成圆圈并标上编号，边画成直线，有向图的边带箭头；自环、双向边（两个方向都有边）也能分清楚。
* **拖拽节点**：鼠标左键按住节点拖动即可改变位置。
* **缩放**：滚轮以光标为中心放大缩小（15% ~ 600%），工具栏也有放大 / 缩小 / 适应窗口。
* **滚动条**：右侧和下方各一条，内容超出窗口时拖滑块浏览整张图（也可以用右键或左键拖空白处平移）。
* **选中节点**：单击节点会高亮它和它的邻居、相邻的边，并在左上角显示这个节点的邻接表。
* **自动布局**：`R` 力导向布局（相连的点会靠拢）、`C` 圆环布局。
* **保存 / 加载**：工具栏「打开图文件 / 保存」或 `Ctrl+O` / `Ctrl+S`，文件格式和 `build_from_file` 完全一致
  （第一行 `n m is_directed`，之后每行一条边）；节点坐标会另存一份 `<文件名>.layout`，下次打开位置就还是原来的样子。
* **导出图片**：`Ctrl+P`（或 `P`）把当前画面存成 PNG，写课程设计报告可以直接贴图。

完整的操作说明在窗口里按 `H` 就能看到。

实现要点（写报告可以直接用）：

1. **世界坐标 + 相机**：节点位置保存在「世界坐标」里（一张和窗口无关的平面坐标）。
   屏幕像素 =（世界坐标 − 相机左上角）× 缩放比例。缩放只改比例、平移只改相机左上角，
   滚动条的位置也换算成相机左上角，所以三者互不干扰，缩放时鼠标指着的那个点不会跑。
2. **按帧刷新**：每帧先把鼠标/键盘消息全部取走（`peekmessage`），再整体重画一遍，
   最后用 `FlushBatchDraw()` 一次性贴到屏幕上（双缓冲，不闪屏，也是后面做 DFS/BFS 动画的现成骨架）。
3. **布局**：力导向布局用的是 Fruchterman-Reingold 的简化版——边像弹簧把相连的点拉近，
   每对点之间又有斥力把点推开，迭代若干轮并逐渐「降温」，点就自己散开了。

实测踩到的三个坑，改代码时注意：

1. 引入 `<graphics.h>` 前必须先 `#define NOMINMAX`，否则 `windows.h` 的 `min`/`max` 宏会把 `std::min`/`std::max` 替换掉，编译直接报错。
2. 本机这版 EasyX 里 `clearcliprgn()` 会把已经画好的内容整块清掉。所以 `ui.cpp` 里没有用裁剪区，
   而是先画图、再画工具栏和状态栏，让它们把超出画布的部分盖住。
3. 源文件是 UTF-8，而 EasyX 按 GBK 显示文字，所以界面上的中文要先转成 GBK 再交给 `outtextxy`
   （见 `ui.cpp` 里的 `gbk()` 函数），否则全是乱码。字体名也一样要转。
4. 控制台也有同样的问题：cmd 默认按 GBK(936) 显示，直接 `cout` UTF-8 的中文会变成
   「鍥剧粨鏋滃疄楠屽钩鍙?」这种乱码。所以 `main.cpp` 里的菜单先用 `console_text()` 按
   控制台当前的代码页转一次再输出（控制台本来就是 UTF-8 的话会跳过转换）。

编译命令里多了 `-lcomdlg32`（「打开 / 保存文件」对话框用到的系统库），`build.bat` 与 `tasks.json` 里已经加好。
